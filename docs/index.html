Also provide instructions how can this be deployed in enterprise environments via policies Done — I created a simple promotional HTML page for the solution: Download the HTML page It presents the extension as an enterprise compatibility/governance control, explains what it does, and includes deployment guidance for Group Policy, Intune, and the Microsoft Edge management service. For enterprise deployment, the cleanest approach is to force-install the extension. Microsoft Edge supports ExtensionInstallForcelist; force-installed extensions are installed silently and users cannot disable or remove them. For Group Policy, install the current Microsoft Edge ADMX templates and go to: Administrative Templates → Microsoft Edge → Extensions → Control which extensions are installed silently Enable it and add either just the extension ID for an Edge Add-ons hosted extension, or for a self-hosted extension: EXTENSION_ID;https://your-company.example/extensions/copilot-studio-classic/update.xml Microsoft specifically documents this extension_id;update_url pattern for self-hosted extensions. For Intune, use an Edge Settings Catalog/configuration policy and configure ExtensionInstallForcelist. You can also use the more granular ExtensionSettings policy. With ExtensionSettings, the relevant configuration is conceptually: { "YOUR_EXTENSION_ID": { "installation_mode": "force_installed", "update_url": "https://your-company.example/extensions/copilot-studio-classic/update.xml" } } force_installed prevents users from disabling or uninstalling it. You can also manage it from the Microsoft Edge management service in Microsoft 365 admin center: select an Edge configuration profile, open Extensions, add the extension by ID, and set the installation policy to Force. Microsoft states that a forced extension is automatically installed and users cannot remove it. For a private enterprise extension, you essentially have two distribution models. The simpler operational model is publishing it through Microsoft Edge Add-ons and controlling deployment by policy. The alternative is self-hosting the .crx and an XML update manifest on your own HTTPS endpoint. Microsoft supports self-hosted enterprise extensions and policy-based force installation. One thing I would explicitly state when promoting this internally: this is a managed workaround/compatibility control, not an official Copilot Studio tenant setting. It currently relies on: AgenticAutomationsShellOptIn = false and on the current Copilot Studio DOM for hiding the promotion.
